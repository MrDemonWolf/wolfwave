# Changelog

All notable changes to this project will be documented in this file.

## [2.1.1] - Unreleased

> The next release. These changes ship on the [Nightly channel](https://mrdemonwolf.github.io/wolfwave/docs/nightly) off `main` until 2.1.1 is tagged for stable, when this heading gets its date.

### Added

- **Five new Stream Deck keys.** **Announce Song** posts what's playing to your chat, same wording as `!song`. **Reject Request** drops the request that's playing and tells chat it went, so the requester isn't left wondering where their song came from and vanished (Skip just moves on silently). **Block Requester** bars the person who requested the current song, held for a second so you can't do it by accident. **Request Access** cycles who can request (Everyone, Subscribers, VIPs & Subs, Mods) and shows the current setting right on the key. **Now Playing** shows the track over its album art and does nothing when pressed.
- **You can block people from requesting, not just songs.** Settings → Song Requests → Blocklist now takes a Twitch username as well as song titles and artists. A blocked person's requests are turned away before WolfWave even looks the song up.
- **A Sponsor link you can turn off.** WolfWave now has a Sponsor item in the menu bar's Help submenu as well as the Help menu and the About pane. If you'd rather not be asked, turn off "Show sponsor links" in Settings, About. The toggle stays put so you can turn it back on, and WolfWave is free and complete either way.

### Changed

- **Buttons that do slow work now show they're working.** Approve, Skip, Hold, Fetch link, Check Again, Add to blocklist, and the developer service controls swap their label for a spinner while the work runs, ignore a second click, and flash a checkmark when they're done. Before, they looked untouched the whole time, so the only way to tell WolfWave had heard you was to click again and hope you hadn't just done it twice.
- **Stream Deck has its own settings page.** It used to share Stream Widgets, with the control token sitting one divider below the overlay token in the same card. Those two do very different things: the overlay token is read-only and reachable from other machines on your network, while the control token runs commands and is only ever accepted from this Mac. Putting them side by side made them look interchangeable. Stream Deck is now its own page under On Stream, holding the control token, the setup steps, and a new **Allow Stream Deck commands** switch. Turn that off and WolfWave refuses every key press while your overlay keeps running, which is what you want if you like the now-playing box on stream but would rather nothing could drive playback. It's on by default, so nothing changes unless you change it.
- **Stream Widgets reads in the order you actually set it up.** Turn the connection on, drop in the ready-made browser source, then style it. The port, the overlay token, and the raw WebSocket addresses moved to the bottom under "Build your own overlay", where they belong, because they're only needed if you're writing your own overlay. Leading with them made a two-click setup look like a programming job. The page also now tells you where the server can be reached (this Mac, or this Mac and your local network) instead of leaving you to guess, and the note explaining why the port is locked sits above the locked field rather than below it, where you'd only find it after wondering what was broken.
- **Stream Deck: three keys removed, and Clear Queue now has to be held.** Discord Presence, Music Sync, and Cycle Theme are gone. All three flipped a setting you set once and then never touch, and a key on a deck is worth more than that; change them in Settings instead. The Status key is gone too. Clear Queue still exists but only fires if you hold it for about a second, because it deletes every request with no undo and a deck is a grid of identical squares under your hand mid-stream. **Update the plugin and WolfWave together** — they check a version with each other, and a mismatch shows `Update` on every key.
- **Stream Deck keys use the whole key.** A key that's on is now a solid blue key rather than a small blue glyph on black, so playing, queue held, and every toggle read from across the room. Clear Queue and Block Song are red because they throw something away, and Approve Next turns amber when requests are waiting. The queue keys print their count as a big number instead of squeezing it into the key label, and the Status key shows four dots, one per link, each in its own service colour, instead of a three-line list that never fit. Those keys also stop overwriting the key title, so a label you set on them now stays.
- **Export Logs now exports everything, not just the newest file.** Settings → Advanced → Export Logs writes a single file containing your app version, macOS version, and install method, the details of the last crash if there was one, and every rotated log file rather than only the current one. Before, if the log had just rolled over you'd send us a nearly empty file while the lines about your problem sat in a backup we never saw. The file is named with the date and time so a second export doesn't overwrite the first, and Copy to Clipboard now includes the same version header.
- **The crash notice says what actually crashed.** After an unexpected quit, the notice in Settings → Advanced now names the fault and when it happened instead of just saying something went wrong, and those details are written into your log so they're in the file you send us. WolfWave recorded this all along and then deleted it unread. "Report a Bug" also fills in the crash, your install method, and log size for you.
- **Logs you can actually read.** Every line now carries a full date and timezone instead of just a clock time, so a log covering more than one day can be put in order. Each launch stamps the app version, build, and macOS version at the top, so a log you send us can be matched to the exact build that wrote it. Numbers that describe what happened (file sizes, timings, ports) are no longer scrubbed out as if they were account IDs, while tokens and account IDs are still removed.

### Fixed

- **The Stream Deck page's cards line up now.** The "Setting it up" card was drawn narrower than the two above it, because it holds only text and a button and so shrank to fit them instead of filling the page like its neighbours.
- **The Stream Deck setup steps described an install you can't do.** Step one told you to get the plugin from the Elgato Marketplace. It isn't there yet — you build it from the repo, which is what the setup guide has said all along. Step four also told you to leave the host alone; there is no host to change, so it now mentions only the port.
- **Hiding the overlay no longer blanks your Stream Deck.** With the overlay cards turned off, WolfWave stopped telling the Stream Deck what was playing, so the Play/Pause key showed the track that happened to be on when you hid them, or nothing at all. Hiding the cards now only hides the cards. As a side effect, WolfWave also stops running its overlay progress timer when a Stream Deck is the only thing connected, since nothing is on screen to animate.
- **Errors now tell you what broke and what to do about it.** Failures used to say things like "Couldn't check channel" with no explanation, and the real reason was only visible if you hovered for a tooltip. Messages now name the cause and come with a button that performs the fix.
- **Twitch errors were invisible.** Around forty failure messages, including every failed channel join and every Keychain problem, were written to a status line that no screen ever displayed. They now appear in the Twitch pane.
- **A missing permission no longer looks like an expired sign-in.** If your Twitch token was missing an optional permission, WolfWave said your session had expired and told you to reconnect, then quietly stopped re-checking the token. It now says exactly which permission is missing, and everything else keeps working.
- **"Your sign-in is fine" when it is.** If Twitch is down, rate limiting us, or you're offline, WolfWave used to blame your sign-in and send you to reconnect, which never helped. Those now say what actually happened.
- **Erase & Reset no longer stops silently.** If macOS refused to remove your saved sign-ins, the reset stopped partway and said nothing, so it looked like everything had been erased when nothing had. It now tells you plainly that nothing was erased.
- **Discord says what went wrong.** "Discord not running" was shown for every connection problem, including ones that happen with Discord open in front of you. WolfWave now distinguishes Discord being closed, Discord refusing the connection, and macOS blocking it.

### Developer

- **The Debug app icon is generated, not a second design.** `AppIcon-Dev.icon` used to be a hand-maintained twin of `AppIcon.icon` with an orange background and its own glyph fills, which meant every change to the wolf mark had to be copied into two places by hand and the dev build didn't look like WolfWave. It is now derived from the Release bundle by `scripts/generate-app-icons.ts` (`make icons`): the same brand-blue fill and the same `logo` layer verbatim, plus a red `DEV` badge across the bottom. The badge follows the [iconwolf](https://github.com/mrdemonwolf/iconwolf) development-badge convention already shipping in ConPaws, down to the pill geometry, with the lettering drawn as a grid of squares rather than SVG `<text>` so it does not depend on a font being installed wherever the icon is compiled. The Release icon is untouched and stays the source of truth. Generation is pure JSON/SVG assembly with no rasterisation, so the output is byte-identical on every host; `scripts/check-generated-drift.sh` now fails the PR if the committed bundle drifts. `PRODUCT_NAME`, the display name, and the `.dev` bundle ID are all unchanged.
- **`raw-status-color` lint rule.** Nothing stopped the next PR from writing `color: .gray` and undoing the token migration, because `ds:lint`'s rules covered font size, spacing, padding, icon buttons, and animation duration only. The rule is scoped to the `color:` / `statusColor:` argument labels, so `.foregroundStyle(.secondary)` on body text is untouched, and it reaches across a ternary. `.black` / `.white`, `.purple`, and `.accentColor` are outside the banned set on purpose, so the deliberate exceptions need no allowlist entries. Its one blind spot is a bare `return .gray`, which carries no argument label; that limit is pinned by a test rather than left to be rediscovered. `lint.ts` now exports `RULES` behind an `import.meta.main` guard so `bun run ds:test` can exercise the patterns against known-good and known-bad lines, since a regex that silently stops matching is indistinguishable from a clean tree. Wired into the `ds-lint` CI job.
- **`DSColor.neutral`, and status chips are finally on tokens.** The design system had `success`, `warning`, `error`, and `info` but no neutral, so every "off / disconnected / stopped" chip fell back to raw `.gray` or `Color.secondary`. That single gap is why 13 `StatusChip` sites still passed system colors while ~40 non-chip tints already used `DSColor`. `neutral` is `#8E8E93` (Apple's `systemGray`, the one system gray whose light and dark variants are identical, so a flat token is correct in both themes) and every state chip now takes a token. Two sites keep a raw color on purpose and say so in a comment: Software Update's "update available" stays `.accentColor` so it follows the user's system accent, and the Discord preview card's off dot stays a white wash because it sits on a fixed Discord-branded surface where the neutral gray reads at 1.9:1. Side effect worth knowing: `Color.secondary` is translucent, so off pills previously rendered a near-invisible background wash next to opaque siblings, and now match. The Twitch "sign-in expired" chip also moves from yellow to the warning orange every other warning chip uses.
- **`StreamDeckPaneStatus`.** The Stream Deck header chip's precedence rule (the shared server outranks the command switch, because commands on a stopped server produce a key that silently does nothing) lived in three computed properties inside the view, where nothing could test it. It is now a pure `nonisolated` resolver with a test suite. `StatusChip.StateGlyph` became `nonisolated` to let it: the module defaults to `MainActor`, which walled a symbol-name vocabulary off from non-view code.
- **End-to-end tests, for real this time.** New `WolfWaveUITests` XCUITest target, scheme, and `make test-ui`, plus a `ui-test` CI job. It builds the app, launches it, and drives it: the onboarding wizard start to finish (Next through every step, Back, Skip All), and Cmd+, followed by every settings pane rendered twice. That second one guards the failure this app has actually shipped, a persisted value outside a picker's tag set trapping inside SwiftUI's layout and taking the settings window down, which no unit test can see because the crash is not in our code. The suite is deliberately off `make test-ci`, so release and nightly stay unit-only and a UI run never gates a release. `apps/native/docs/end-to-end-testing.md` records what is automated and what still genuinely needs a human.
- **The Stream Deck control protocol is now tested across the wire.** `StreamDeckCommandTests` parses envelopes as strings with no transport and `WebSocketServerAuthTests` settles handshakes without sending a command through one, so the seam between them — reading a frame off the socket, dispatching it to the handler, acking on the originating connection — could break with both suites green. New `StreamDeckControlIntegrationTests` drives a real loopback WebSocket: a control client's command reaches the handler and is acked, an overlay client's identical command is refused `unauthorized` and never reaches the handler, and a stale protocol version is rejected without running. The overlay case is the one that matters most — that token goes to an OBS browser source, and a regression letting it drive the app would fail no pure-parse test, because the envelope is perfectly valid and only its origin is wrong.
- **`UITestMode`, the out-of-process test seam.** A UI test runs the app in its own process, where `XCTest.framework` is never loaded, so `WolfWaveApp.isRunningTests` is false and every isolation seam keyed on it resolved to the live one — a UI test toggling a setting would have edited the developer's real `com.mrdemonwolf.wolfwave.dev` domain and real Keychain, the exact corruption `DefaultsStore` exists to prevent. `DefaultsStore` and `KeychainService` now branch on `UITestMode.isUnderTestHarness`, which covers both harnesses. The same flag keeps `AppleMusicSource`, `TwitchChatService`, `DiscordRPCService`, and Sparkle from starting, so the suite needs no account, no network, and never raises the Automation prompt. `@AppStorage` follows too, via `.defaultAppStorage(DefaultsStore.store)` on the Settings scene and the onboarding host — in a normal launch that resolves to `.standard` and nothing changes.
- **CI/CD deduplicated.** The build preamble (Bun, caches, design tokens, widget, `Config.xcconfig`, `SponsorConfig`, SwiftPM cache) lived in five places across CI, Release, and Nightly; it is now the `.github/actions/setup-native-build` composite action. The ~90-line inside-out signing and notarization block lived in two; it is now `scripts/codesign-app.sh`, `scripts/notarize-dmg.sh`, `scripts/import-signing-cert.sh`, and `scripts/generate-appcast.sh`, which `make notarize` also uses. Three drifting copies of the `xcodebuild test` invocation collapsed onto `make test-ci`, so CI runs exactly what a contributor runs.
- **CI gates at the job level.** One `changes` job runs `dorny/paths-filter` once and every other job keys off its outputs, replacing five duplicated filter blocks and ~25 per-step `if:` conditions. A docs-only PR now reports the native jobs as skipped instead of running them as no-ops.
- **`make check-drift`.** Regenerates the widget, design tokens, and `SponsorConfig`, then fails on drift with the fix command named per group — the same gate CI runs, available before you push.
- **Docs deploys are path-filtered.** A Swift-only push to `main` no longer rebuilds and republishes the site; `workflow_dispatch` forces one.
- **Scheduled workflows skip forks.** Nightly, Update Sponsors, and Copyright Year now no-op outside `MrDemonWolf/wolfwave` instead of failing on secrets a fork can't have.
- **CI builds get the real fork-branding URLs.** Every workflow wrote `DOCS_URL` and `COMMUNITY_DISCORD_URL` into `Config.xcconfig` without the `$()` escape, so xcconfig truncated both to `https:` and `AppConstants.validURL` silently fell back to the compiled-in defaults.
- Log lines are now strictly parseable without giving up readability. The format is `<ISO8601>  <LEVEL>  <Category>  <File.swift:line>  <message>[ key=value…]`, resting on one invariant: a record starts with an ISO-8601 timestamp at column 0, and a line starting with whitespace is a continuation of the record above it. Levels lost their emoji (`ℹ️ INFO` → `INFO`): emoji are multi-codepoint, variable-width in bytes, impossible to column-align, and made `grep -c ERROR` ambiguous against message text. `clearLogFile()` used to hand-build a second, incompatible line shape that broke any parser on contact; it now goes through the same builder as every other record. Multi-line messages (a `CrashReporter` reason, an `error.localizedDescription`) are indented so they can never be mistaken for records. New `Log.Fields` (`KeyValuePairs`) renders an optional quoted `key=value` tail, additive so existing call sites compile unchanged. New pure `Core/LogRecord.swift` is the canonical reader for the Debug viewer, the export composer, and external tooling, with 25 tests that round-trip the writer against it so the two cannot drift. Grammar written up in `apps/native/docs/logging-format.md`.
- Redaction stopped destroying diagnostic evidence. The blanket `\b\d{6,}\b` rule rewrote every 6+ digit number to `[USER_ID_REDACTED]`, so byte counts, millisecond durations, ports, and epoch values were all unreadable in the one artifact a user hands over. It is now (a) digits in an identifier context, keeping the key and replacing only the value, and (b) a bare-digit floor raised to 9. Structured field values are redacted by key: a sensitive-key set (`token`, `user_id`, …) is replaced wholesale, and a numeric-safe set (`bytes`, `ms`, `port`, `code`, …) skips the bare-digit rule entirely, so `bytes=1073741824` survives. Field keys are never redacted. Both directions are pinned by tests: identifiers still die, diagnostic numbers still survive. Also fixes a stale comment in `LoggerTests` that documented the threshold as `\d{8,}` when the code said `\d{6,}`, which is how its fixture got chosen against the wrong rule.
- `clearLogFile()` could leave a multi-hundred-KB file of NUL bytes. It seeked and truncated through the live `FileHandle`, which keeps its own write offset; a write landing at the stale offset re-extended the freshly truncated file with a NUL gap exactly the size of the old log. Observed as a 306 KB log clearing to a 306 KB file of zeroes, and the old `lineCount == 1` assertion passed anyway because NUL bytes contain no newlines. Clearing is now an atomic whole-file replace with no offset to go stale. `writeToFile` also compares the file's inode against the one its handle was opened on and reopens when they differ, so a factory reset replacing the container no longer leaves the logger writing into an unlinked inode forever. Both pinned by tests.
- `Log.error` no longer blocks its caller on an `fsync`. It ran `fileQueue.sync { synchronize() }` at 165 call sites, serializing every caller behind a disk sync during exactly the error bursts (reconnect loops, bind failures) where throughput matters. It now schedules the flush on the same serial queue, which preserves ordering without stalling; `shutdown()`, `exportLogFile()`, and the `CrashReporter` NSException path keep the blocking flush. `logLineCount()` memoizes against the file's size and modification date instead of restreaming up to 5 MB under `fileQueue.sync` on every settings-pane refresh. `WOLFWAVE_LOG_LEVEL` now gates the file sink as well as OSLog, which its name always implied; under XCTest that default of `.error` also removes most of the cross-suite churn that used to rotate the shared log mid-test.
- Log rotation keeps 3 backups instead of 1 (5 MB each, 20 MB worst case), with ordered shifting and a new `Log.rotatedLogFiles()` for export paths. A single backup let a tight reconnect loop rotate twice in seconds and evict the original failure. Each rotated file gets its own session banner, so a backup is still attributable to a build.
- **Fixed a flaky test race on the shared settings store.** `DefaultsStore` gives the test host its own `UserDefaults` suite, but one suite per *process*, shared by every concurrently running test. Swift Testing suites run in parallel with each other and with XCTest, so `SongRequestServiceTests` could set `songRequestEnabled = true` in `setUp()` and have another suite flip or wipe it before the assertion, failing with `featureDisabled` while passing in isolation. `KeychainBackendTestIsolation` became `SharedTestStateIsolation` and now covers the defaults store alongside the Keychain backend and the reauth flag, as one lock rather than two that could deadlock against each other. XCTest suites take it by subclassing `WolfWaveTestCase`, Swift Testing suites via the new `.isolatedSharedTestState` trait; scopes are re-entrant so the two can nest. `SharedTestStateIsolationTests` pins the contract.
- Post-merge review fixes on that isolation work: `TwitchTokenRefreshTests` and `TwitchTokenLifecycleTests` now acquire the shared-state lock *before* resetting redemption defaults instead of after, and `KeychainServiceTests` restores `Preferences.twitchReauthNeeded` to its prior value on the way out, since both the suite and `KeychainService` itself can flip it.

## [2.1.0] - 2026-08-14

### Security

- **Safer local widget credentials.** Token-bearing HTML is served only to a true loopback peer using a literal local Host and is marked `no-store`; token changes are saved to Keychain before connected clients rotate.

### Added

- **Custom bot commands.** Make your own chat commands with a fixed reply, right in Settings → Twitch → Custom Commands. Drop in variables like `$user`, `$touser`, `$args`, `$1`–`$9`, `$song`, and `$lastsong` and they fill in live. Each command gets its own aliases and Everyone / Per-person cooldowns, same as the built-ins.
- **Pick who can run a command.** Set any custom command to Everyone, Subscribers, VIPs, Moderators, or Broadcaster only. Custom commands ride along with your settings backup.
- **Approve songs before they play.** New opt-in "Require My Approval" toggle in Settings → Song Requests → Access. When it's on, every request (chat, channel points, bits) waits in the Queue tab until you approve or decline it. Off by default, so requests still auto-queue unless you turn it on.
- **Fair-share song ordering.** The queue now interleaves requests round-robin, so everyone's first request plays before anyone's second. A regular who re-types fast no longer plays back-to-back while newcomers wait. On by default; flip "Fair-Share Ordering" off in Settings → Song Requests → Queue for classic first-in, first-out.
- **Sub / VIP request priority.** Reward your subs, VIPs, and mods: pick a perk in Settings → Song Requests → Queue. "Skip cooldown" lets them request without the wait; "Jump the queue" also moves their song ahead of regular requests within the same fair-share round (so it's a nudge up, not a queue takeover). Off by default.
- **Two new overlay layouts: Vinyl and Classic.** Vinyl is a spinning record with your album art as the label and a circular progress ring. Classic sets the album tile beside a card with the title, artist, and a progress bar. Pick either in Settings → Stream Widgets, same as Horizontal, Vertical, and Compact.
- **Queue ticker overlay.** Add `?queueTicker=1` to your widget URL for a panel showing the next 3 song requests, title and requester, so viewers see their spot in line. Off by default, matches your current widget theme.

### Changed

- **A custom WolfWave mark.** The familiar wolf now carries a padded side equalizer, used consistently across the app icon, menu bar, onboarding, OBS fallback, Discord art, DMG installer, docs, and repository branding.
- **Settings toggles all look the same now.** Launch at Login, "Check automatically" (Software Update), and "Collect on-device diagnostics" (Advanced) now use the standard row: name and short description on the left, switch on the right. Same layout as every other toggle in Settings.
- **Lighter on your Mac.** WolfWave does a lot less work between songs now. Chat lines that aren't commands bail out immediately, the request poller sleeps when nothing is playing and the queue is empty, and Discord and your overlay only get an update when something actually changed instead of every few seconds. The History pane stopped re-sorting your whole play log twice on every redraw. Same features, less CPU and battery.
- **Lighter OBS overlay.** Progress painting is batched at 10 Hz, and animation work stops while the page is hidden or unloaded and when reduced motion is enabled.
- **Less background work.** WolfWave now pauses unused overlay, Twitch, song-request, and Discord tasks instead of polling or retrying while those features are idle, disconnected, held, hidden, or disabled.
- **What's New only shows up for feature releases.** The window used to reappear after every version bump, including bug-fix ones, showing a stale feature list. It now opens once per release that actually ships features.
- **Dev builds have their own app icon.** If you build WolfWave from source, the Debug app now carries an orange icon instead of the blue one, so **WolfWave Dev** and the release app are easy to tell apart in the Dock and the app switcher. Nothing changes for anyone installing from a DMG or Homebrew.

### Fixed

- **Settings no longer crashes on an out-of-range saved value.** If a setting on disk held a value the control couldn't show, opening that pane could take the whole Settings window down instead of just looking wrong. The Song Requests pane did exactly that with a bad vote-skip window. Saved values are now checked as they're read, and anything out of range or corrupted shows as that setting's default until you change it.
- **Song request setup now checks the playlist Music can actually see.** WolfWave makes the WolfWave Requests playlist in your Apple Music library, but songs play out of the Music app on this Mac. Setup only ever checked the first half, so it could tell you everything was ready while requests had nothing to play from. It now asks Music directly, and says so plainly if Music can't see the playlist, pointing you at Sync Library in Music, Settings, General. It's a heads-up, not a lockout: song requests stay on, and there's a Check Again button for once you've flipped it.
- **Settings backups now restore live behavior, not just switches.** Appearance, update settings, and Launch at Login take effect during import; pending login-item approval points to System Settings, invalid or unrepresentable values are ignored, Song Requests stay off until setup is complete, and the preview count matches what will actually restore. Backups created by WolfWave 2.1.0 require 2.1.0 or newer to import; backups from earlier versions still import into 2.1.0.
- **Notifications no longer stack or arrive out of order.** A new song or skip-vote banner clears both the queued and the already-shown banner it replaces, banners of the same kind are posted one at a time so a slow older one can't appear after a newer one, and a slow old artwork lookup can no longer overwrite the latest notification.
- **Cleared artwork stays cleared.** An artwork lookup already in flight can no longer refill the cache after you clear it, and artist/title combinations containing punctuation no longer share cache entries.
- **Pasted music links resolve reliably.** Song requests now find the first supported link in a message, ignore surrounding punctuation, and reject insecure or lookalike Apple Music URLs.
- **Twitch sign-in survives service hiccups.** Device-code login now uses the original expiry deadline, follows the required polling slowdown and timeout backoff, and keeps trying through rate limits plus temporary network or server failures instead of failing early.
- **Twitch no longer mistakes an outage for an expired sign-in.** Only Twitch's explicit token rejection or confirmed missing permissions prompts a reconnect. Network errors, rate limits, and malformed refresh responses retry within a bounded window and leave saved credentials intact when Twitch remains unavailable.
- **Disconnecting Twitch no longer gets stuck after a refund write fails.** If WolfWave couldn't save a channel-point refund to disk and the account was then switched or removed, it kept retrying against credentials that no longer existed and held Disconnect open. It now stops once nothing can act on that redemption. The points are still refunded: the next sign-in for that reward reads your unfulfilled redemptions straight from Twitch and settles them before the reward goes live again.
- **Twitch account changes stay internally consistent.** Access tokens, refresh tokens, account identity, and the configured channel now change together in one Keychain write. Existing saved fields migrate without deleting the originals until the new record is safe. Imported and edited channel names are checked with Twitch before becoming canonical; invalid, missing, stale, or temporarily unverifiable names stay pending.
- **Settings backups preserve authored rules.** Custom bot commands and the Song Request blocklist now round-trip with other portable preferences, and Reset Settings clears the centralized blocklist data.
- **A backup that can't be applied safely is refused outright.** Custom commands with a blank, duplicated, or clashing trigger, or with cooldowns the sliders can't represent, stop the import instead of half-landing. A file saved in an older, unsupported format now says so plainly rather than failing with a generic error. Blocked titles and artists get trimmed and checked on the way in, and keep the date you added them.
- **Channel names are tidied on the way in and out.** An imported or exported Twitch channel name is cleaned up the same way the connect screen does it, so a stray space or a pasted URL fragment can't leave you with a channel that never connects.
- **Slow Twitch commands no longer hold up chat.** Song requests and custom commands run as tracked connection work, so keepalives and later messages continue; disconnecting or switching channels cancels old replies before they can land in the wrong chat.
- **Paid Twitch actions recover after quits and outages.** Channel-point intake and fulfill/refund outcomes are durable until Twitch acknowledges them. Qualifying Bits cheers persist the complete boost/request action before queue work and replay after relaunch. If local recovery storage fails, WolfWave pauses the managed reward, shows a warning, and still gives an already-paid Bits cheer one process-owned attempt.
- **Discord presence replies no longer cross wires or hang indefinitely.** Each local IPC command consumes the response with its own nonce, the handshake accepts only Discord's READY dispatch, and stalled local connects or replies now stop at one bounded deadline.
- **Duplicate Twitch commands stay single-shot.** Command message IDs keep their complete replay window even in busy chat, including while commands are disabled, so delayed EventSub redelivery cannot rerun queue or playback actions.
- **Local WebSocket peers can no longer hold unlimited resources.** WolfWave caps pre-handshake peers, expires stalled handshakes, limits inbound messages to 16 KiB, and cleans every old listener generation before retrying.
- **Stream Deck reconnects no longer crash while a socket is still opening.** Retiring a connecting socket now keeps the required error sink until close.
- **Stream Deck control is local-only and no longer shares your overlay secret.** WolfWave now keeps separate read-only overlay and control tokens. Stream Deck protocol v2 always connects to this Mac, so LAN widgets can still receive track data but can never run playback or queue commands. After updating, copy the new **Stream Deck Control Token** into the plugin once.
- **Twitch custom commands stay locked while disconnected.** The settings card now explains that Twitch must be connected and closes an open editor if the connection becomes unavailable.
- **The custom-command editor catches clashing aliases.** It used to flag only a duplicated trigger, so an alias that shadowed another command slipped through and one of the two commands never fired. Commands saved before this check are cleaned up the next time WolfWave loads them.
- **Twitch stays connected when its server moves you.** Twitch periodically hands your connection to a different server. WolfWave could flash "disconnected" and tear down the new, healthy connection while doing that. It rides through cleanly now.
- **Low Power Mode no longer stalls launch.** Startup reads the posted power-state snapshot without recursively initializing the monitor.
- **Discord presence settings apply immediately.** Idle presence and "hide while paused" changes refresh at once, preserve the paused track for restoration, and stay hidden when Discord is enabled mid-pause.

It was `Song?` only so tests could build an item without one, which made "a queue item that cannot be played" a legal state that nothing outside a test fixture ever produced, and forced a nil branch into both `SongRequestService.performPlayback` and `AppleMusicController.performTargetedPlayback`. Both branches are gone, and `SongRequestQueueView`'s rebuild list drops a `compactMap` that could only ever have discarded a test fixture. The song-less initializer is deleted; tests build items through `makeTestRequestItem`. The Debug tab's fake-request injector needed real songs too, so the Apple Music resource-shape decode moved to `Song.debugPlaceholder` in the app target under `#if DEBUG` and the test factory delegates to it — one copy of that shape, so a MusicKit change breaks both together instead of letting them drift.
- Test-quality pass on the backup and artwork suites: `SettingsBackupCoderTests` compares persisted models instead of raw encoded bytes (byte equality was brittle against key ordering), blocklist round-trips are compared by semantics rather than encoding, `ArtworkServiceNetworkTests` uses isolated mock URL sessions, and the notification test double reports an authorization status.
