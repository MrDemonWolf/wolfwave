Something broke? Find the message WolfWave showed you, or the symptom, below. Each section says what happened and what to do.

Most error banners in WolfWave already have the fix button on them. Some also have a **Learn More** link that lands on the matching section here.

**Still stuck?** Go to **Settings → Advanced** and click **Export Logs**. It saves one file with your app version, macOS version, the last crash (if any), and every log WolfWave still has. Logs never contain tokens. Attach it to a [GitHub issue](https://github.com/MrDemonWolf/wolfwave/issues/new).

## Twitch

If your network drops, WolfWave reconnects on its own. It retries fast at first, then about once a minute. Waking your Mac starts the fast retries again.

### Chat commands don't reply [#commands-not-replying]

Check these in order:

1. **Is Twitch connected?** **Settings → Twitch** should show your channel.
2. **Is the command on?** `!song` and `!last` are on for new installs. `!wolfwave`, `!stats`, and `!playlist` start off. See [Turn commands on](/docs/bot-commands#turn-commands-on).
3. **For `!sr`: is Song Requests on?** **Settings → Song Requests → Enable Song Requests**.
4. **Is "Only reply while live" on?** **Settings → Twitch → Chat commands**. If it is, commands stay quiet until you go live.
5. **Cooldown?** A command waits a few seconds between uses. Mods and you skip cooldowns, so test from a viewer account to see what viewers see.
6. **First word?** The command must start the message. `hey !song` won't work.

### Sign-in expired [#twitch-sign-in-expired]

**Message:** "Twitch sign-in expired"

**Why:** WolfWave refreshes your sign-in in the background. That can fail if you removed WolfWave's access on Twitch, changed your Twitch password, or didn't use it for a long time.

**Fix:** Click **Reconnect with Twitch**. Your channel, commands, and settings stay as they were.

### That code expired [#twitch-code-expired]

**Message:** "That code expired"

**Why:** Each Twitch sign-in code expires. Twitch sets how long it lasts, and the code on screen shows the time left.

**Fix:** Click **Get a new code** and approve it on Twitch.

### Twitch sign-in didn't finish [#twitch-sign-in-failed]

**Message:** "Twitch sign-in didn't finish"

**Why:** The sign-in stopped before it was done. The line under the message says why:

- "You declined the authorization on Twitch." You said no on Twitch's page.
- "Twitch didn't return a refresh token." Twitch approved it but didn't send back what WolfWave needs to stay signed in.
- Anything about the network or an invalid reply. The connection to Twitch dropped or was blocked.

**Fix:** Click **Try Again** and approve the new code on Twitch. Still failing? See [Still stuck](#still-stuck).

### Couldn't confirm which account is posting [#twitch-account-unconfirmed]

**Message:** "Couldn't confirm which account is posting"

**Why:** You signed in, but WolfWave couldn't look up which Twitch account that is. It needs that to post chat replies as the right account.

**Fix:** Click **Reconnect with Twitch**. Still failing? See [Still stuck](#still-stuck).

### Couldn't sign out of Twitch [#twitch-sign-out-failed]

**Message:** "Couldn't sign out of Twitch" or "Couldn't switch Twitch accounts"

**Why:** WolfWave couldn't disconnect from Twitch first. You're still signed in, and nothing was removed.

**Fix:** Click **Try Again**. If the message says macOS wouldn't remove the saved sign-in, see [Couldn't save your Twitch sign-in](#keychain-write-failed).

### Couldn't read your saved Twitch sign-in [#twitch-keychain-read-failed]

**Message:** "Couldn't read your saved Twitch sign-in"

**Why:** macOS blocked WolfWave from reading the Keychain, where your sign-in is stored. WolfWave didn't delete it. It just couldn't read it this time.

**Fix:**

1. Click **Try Again**.
2. If it keeps happening, sign in once more.
3. Still failing? Follow the Keychain steps in [Couldn't save your Twitch sign-in](#keychain-write-failed).

### Not signed in to Twitch [#twitch-not-signed-in]

**Message:** "Not signed in to Twitch"

**Why:** WolfWave couldn't find a saved Twitch sign-in when you clicked **Join Channel**. It was removed, or macOS wouldn't let WolfWave read it.

**Fix:** Click **Reconnect with Twitch** and approve the code on Twitch. Then join your channel again. If it keeps happening, see [Couldn't read your saved Twitch sign-in](#twitch-keychain-read-failed).

### "Your sign-in is fine" [#sign-in-is-fine]

**Why:** Your sign-in works. Twitch refused one request for another reason. Reconnecting won't help.

| Message | What happened | What to do |
|---|---|---|
| "Your sign-in is fine, we're being rate limited" | Too many requests in a short time | Wait a moment, then **Try Again** |
| "Your sign-in is fine, Twitch isn't" | Twitch had a server problem, or refused the lookup | Wait a minute, then **Try Again** |

### No Twitch channel by that name [#channel-not-found]

**Message:** "No Twitch channel by that name"

**Why:** Usually a typo.

**Fix:** Use the name from your channel's web address, not your display name. If your page is `twitch.tv/graywolf`, the channel is `graywolf`.

- Letters, numbers, and underscores only.
- 25 characters or fewer.

### That channel name won't work [#channel-name-invalid]

**Message:** "That channel name won't work"

**Why:** The name breaks a Twitch naming rule, so WolfWave didn't even ask Twitch. The line under the message says which rule:

| Line under the message | What to do |
|---|---|
| "Enter the channel WolfWave should join." | The field is empty. Type your channel name. |
| "Twitch names are 25 characters or fewer." | Shorten it. |
| "Use only letters, numbers, or underscores." | Remove spaces and symbols. |
| "Update it and choose Join." | The channel WolfWave was about to save (for example from a backup) isn't a valid name. Fix it, then click **Join Channel**. |

Not sure what your channel name is? See [No Twitch channel by that name](#channel-not-found).

### Couldn't check channel [#channel-check-failed]

**Message:** "Couldn't check channel"

**Why:** WolfWave couldn't confirm your channel exists, so it didn't join. The message shows under the channel name, with the reason right after it, like "Couldn't check channel. Authentication failed". A banner above often has the fix:

| Reason after the message | What to do |
|---|---|
| "Authentication failed" | See [Sign-in expired](#twitch-sign-in-expired). |
| "Your sign-in is fine…" | See ["Your sign-in is fine"](#sign-in-is-fine). |
| "Could not safely disconnect" | See [Couldn't switch channels cleanly](#twitch-switch-channel-failed). |
| Anything else | See [Couldn't connect to Twitch chat](#twitch-connection-failed). |

### Couldn't switch channels cleanly [#twitch-switch-channel-failed]

**Message:** "Couldn't switch channels cleanly"

**Why:** WolfWave couldn't leave the old channel, so it stayed put. This can happen when you join a new channel or click **Leave Channel**.

**Fix:** Click **Try Again**, or click **Join Channel** again.

### Twitch didn't respond [#twitch-no-response]

**Message:** "Twitch didn't respond"

**Why:** The connection to Twitch timed out. A firewall or VPN can cause this. So can a Twitch outage.

**Fix:**

1. Click **Try Again**.
2. Still timing out? Turn off your VPN, or check that your firewall lets WolfWave connect to the internet.

### Couldn't connect to Twitch chat [#twitch-connection-failed]

**Message:** "Couldn't connect to Twitch chat"

**Why:** WolfWave couldn't join your chat. The line under the message says why, for example "Twitch is still unavailable. Retrying in about a minute." Usually your network dropped or Twitch is having trouble.

**Fix:** Wait a moment, then click **Try Again**. WolfWave also keeps retrying on its own. Still failing? See [Still stuck](#still-stuck).

### WolfWave couldn't start its Twitch connection [#twitch-service-unavailable]

**Message:** "WolfWave couldn't start its Twitch connection"

**Why:** WolfWave's Twitch service wasn't running when you clicked **Join Channel**. That's a WolfWave problem, not something you did.

**Fix:** Quit and reopen WolfWave. If it happens again, click **Report a Bug…** on the banner.

### Missing a Twitch permission [#twitch-missing-permission]

**Why:** Your sign-in works, but it's missing a permission a feature needs. WolfWave asks for every permission when you sign in, so you only see this on a sign-in made with an older WolfWave.

| Feature | Permission it needs |
|---|---|
| Channel-point requests | `channel:manage:redemptions` |
| Bit requests | `bits:read` |
| Vote-skip with Twitch Polls | `channel:manage:polls` |
| Custom commands sent as Announcements | `moderator:manage:announcements` |

**Fix:** Click **Reconnect with Twitch**. This is the one time reconnecting a working sign-in is right: a background refresh can't add a permission you never gave. Everything else keeps working until you do.

**Channel points and Bits also need:**

- The tool enabled in Twitch's Creator Dashboard, plus Twitch API access for the feature. Twitch's third-party API restrictions can differ from dashboard access; follow the setup error shown in WolfWave.
- Your **broadcaster** account. A separate bot account can't manage your channel's rewards.

### WolfWave isn't set up for Twitch [#twitch-client-id]

**Message:** "WolfWave isn't set up for Twitch"

**Why:** This copy of WolfWave has no Twitch Client ID, or Twitch didn't accept the one it has. You'll normally only see this on a build you made yourself.

**Fix:** [Download WolfWave](/docs/installation), or set `TWITCH_CLIENT_ID` in `apps/native/WolfWave/Config.xcconfig` and rebuild. See [Development](/docs/development).

### Commands stopped replying, but Twitch looks connected [#chat-replies-rejected]

**Why:** WolfWave can read chat, but Twitch is refusing the messages it sends.

**Fix:**

1. Reconnect Twitch.
2. If it happens again, check whether the account WolfWave signed in with is banned or timed out in your channel. This happens to bot accounts.

## Apple Music

WolfWave notices song changes within a second, and checks again every 5 seconds as a backup. Low Power Mode slows the backup check.

### Let WolfWave read what's playing [#music-permission]

**Message:** "Let WolfWave read what's playing."

**Why:** macOS asks before one app can control another. WolfWave needs this Automation permission to read the current song. It also uses it to play song requests and the menu bar's playback buttons.

**Fix:**

1. Click **Open System Settings**.
2. Go to **Privacy & Security → Automation → WolfWave**.
3. Turn on **Music**.

Still says off? Quit and reopen WolfWave. macOS sometimes doesn't pass a new permission to an app that's already running.

### Now playing is wrong or empty [#music-stopped-responding]

You see an old song, or no song, while Music is open and playing.

**Why:** WolfWave asks the Music app what's playing. If Music is stuck or slow to answer, the card can lag behind, show an old song, or go blank.

**Fix:**

1. Check the permission first. See [Let WolfWave read what's playing](#music-permission).
2. Quit and reopen Music, then play a song. WolfWave picks it up on its own.
3. Still wrong? Click **Export Logs** in **Settings → Advanced** and [open an issue](https://github.com/MrDemonWolf/wolfwave/issues/new).

### Music can't see your requests playlist [#playlist-not-synced]

**Message:** "Music can't see WolfWave Requests yet" (setup) or "Music on this Mac can't see your WolfWave Requests playlist" (**Settings → Song Requests**).

**Why:** Requests are added to your Apple Music library online, then played from the Music app on this Mac. If **Sync Library** is off, the Music app never sees them. WolfWave waits about 40 seconds for iCloud to sync before it shows this, so a brand-new playlist doesn't trip it.

**Fix:**

1. In Music, open **Settings → General**.
2. Turn on **Sync Library**.
3. In WolfWave, click **Check Again**. It waits for sync again before it answers.

### Song Requests playlist banners [#song-requests-banners]

A banner at the top of **Settings → Song Requests** says when your requests playlist needs attention. Each one has a button that does the fix:

| Message | What happened | What to do |
|---|---|---|
| "Your WolfWave Requests playlist is gone. Set up song requests again to rebuild it." | The playlist was deleted and WolfWave couldn't make it again. Song Requests switch off. | Click **Set Up Again**, finish the steps, then turn Song Requests back on. |
| "Your song list link stopped working. Re-share your requests playlist so !playlist works again." | The playlist isn't public anymore, so `!playlist` is off. Requests keep playing. | Click **Re-share Playlist**. Click **Open in Music**, share the playlist, then click **Fetch link**. |
| "WolfWave lost access to Apple Music. Grant access again to keep song requests playing." | Apple Music access, or your subscription, is gone. | Click **Grant Access** and allow it. |

No prompt after **Grant Access**? You denied it before. Turn on WolfWave in **System Settings → Privacy & Security → Media & Apple Music**, then click it again. Also check that your Apple Music subscription is active.

The fourth banner, "Music on this Mac can't see your WolfWave Requests playlist…", has its own section: [Music can't see your requests playlist](#playlist-not-synced).

### Artwork or song links are missing [#artwork-or-song-links-are-missing]

**Why:** WolfWave looks up artwork and links by song title and artist. A failed lookup waits at least a minute before it tries again, longer after repeated failures.

**Fix:** Usually nothing. It fills in on a later song. Restarting WolfWave clears the wait.

## Discord

Discord updates are combined and sent at most about once every 4 seconds, so a fast skip shows the final song, not every song in between.

### Discord isn't connecting [#discord-not-connecting]

WolfWave tells you which of three problems it is:

| Message | What happened | What to do |
|---|---|---|
| "Discord isn't running" | No Discord app found | Open Discord. WolfWave connects on its own. |
| "Discord refused the connection" | Discord is running but said no | Restart Discord |
| "WolfWave can't reach Discord" | macOS blocked the connection | Restart WolfWave. If it keeps happening, send a bug report. |

You need the Discord **desktop app**. Discord in a web browser can't show WolfWave's status.

### Not configured [#discord-client-id]

**Why:** This copy of WolfWave was built without a Discord Application ID. Like the Twitch one, you only see this on a build you made yourself.

**Fix:** [Download WolfWave](/docs/installation), or set `DISCORD_CLIENT_ID` in `Config.xcconfig` and rebuild.

## Stream widgets (OBS overlay)

### The overlay stopped updating [#overlay-not-updating]

**Why:** Almost always the port or the overlay token changed, and OBS still has the old address.

**Fix:**

1. Open **Settings → Stream Widgets**.
2. Copy the address again.
3. Paste it into your OBS browser source.

Making a new token breaks every address that used the old one. That's on purpose.

### Port already in use [#port-in-use]

**Message:** "Couldn't start" on Stream Widgets. It says the port "may be in use". The Stream Deck pane shows **Server error**.

**Why:** Another app on your Mac is already using that port. While **Enable Stream Widgets** is on, WolfWave keeps trying every few seconds, so the error can clear on its own if the other app quits. If it doesn't, pick a different port.

**Fix:**

1. Turn **Enable Stream Widgets** off. (The **Port** field is locked while it's on.)
2. In **Build your own overlay**, enter a different **Port**.
3. Turn **Enable Stream Widgets** back on.
4. Tell OBS about the new port. Add `?port=` and the new number to the end of your Browser Source address. If the address already has a `?`, use `&port=` instead.
5. Using Stream Deck? Change **Port** in the plugin to match. See [Stream Deck](/docs/streamdeck).

An invalid port isn't saved. The field says "Not saved" and keeps your old port.

**Widget page won't load?** It has its own port, and a busy one shows no banner. In **Widget Setup**, turn **Enable Widget Webpage** off, change **Widget Port (Advanced)**, turn it back on, then copy the link again. WolfWave tries a few times when that port is busy, then stops until you turn the switch off and on.

### That token won't save [#widget-token]

**Why:** A token must be exactly 64 characters, using only `0`–`9` and `a`–`f`. The overlay token and the Stream Deck control token must also be different.

If saving fails, your current token stays active, so OBS keeps working.

## Stream Deck

The plugin shows what's wrong right on the keys.

### Every key says Offline [#streamdeck-offline]

**Why:** One of these:

- WolfWave isn't running.
- The Stream Widgets server is off or couldn't start. The Stream Deck pane says **Server off**, **Server error**, or **Starting**.
- No control token is pasted into the plugin yet.
- WolfWave rejected the token.

**Fix:**

1. Open WolfWave.
2. Turn on the server in **Settings → Stream Widgets**. Stream Deck uses the same server, even if you don't use the overlay.
3. If the plugin's panel says "WolfWave rejected this token", copy **Stream Deck Control Token** again from **Settings → Stream Deck** and paste it into the plugin. The token changes when you make a new one, and the overlay token won't work here.

### Every key says Token? [#streamdeck-token]

**Why:** The token in the plugin isn't a full control token. It must be 64 characters. (A blank token shows **Offline** instead.)

**Fix:** Copy **Stream Deck Control Token** from **Settings → Stream Deck**. Paste it into any one key's settings in the Stream Deck app. Every key shares it.

The panel says **Token format is valid** when the shape is right, and **Connected** once WolfWave accepts it.

### Every key says Update [#streamdeck-update]

**Why:** WolfWave and the plugin speak different protocol versions. Keys look normal until you press one, then every key switches to **Update**. The panel says "Update the plugin."

**Fix:** Update WolfWave, install the current plugin, then reload it in the Stream Deck app. Setup steps: [Stream Deck](/docs/streamdeck).

## Settings and data

### Reset stopped partway [#reset-stopped-partway]

**Message:** "Reset Stopped Partway"

**Erase All Data & Reset** (**Settings → Advanced → Danger Zone**) first disconnects Twitch, then removes your saved sign-ins, then clears everything else. The alert tells you how far it got:

- **"…so nothing was erased."** Twitch couldn't disconnect, or your saved sign-ins couldn't be removed. Click **OK**, then try again. If it keeps failing, restart WolfWave and retry. Still failing? Restart your Mac.
- **"…your history and logs couldn't be erased."** Your settings and sign-ins are already gone. Click **Relaunch** to finish. If it keeps happening, restart your Mac.

### That backup file won't import [#backup-not-recognized]

**Message:** The **Couldn't Import** alert, with one of these:

| Message | What happened | What to do |
|---|---|---|
| "That file couldn't be read. It may be damaged or not a WolfWave backup." | The file is damaged, or it isn't a backup | Pick the file you saved with **Export Settings**, or export a fresh one |
| "That's not a WolfWave settings file." | It's a valid file, but WolfWave didn't make it | Pick the file you saved with **Export Settings** |
| "This backup was made by a newer version of WolfWave. Update WolfWave, then try again." | The backup came from a newer WolfWave than yours | Update WolfWave in **Settings → Software Update**, then import again |
| "This backup uses an unsupported settings format." | The file says it uses a settings format WolfWave doesn't accept. That usually means it was edited or damaged | Export a fresh backup from the Mac that made it |
| "That backup is too large to import. Choose a file under 1 MB." | The file is over 1 MB. A WolfWave backup is a small text file, so this is probably the wrong file | Pick the right file |

Backups come from **Settings → Advanced → Export Settings**. See [Backup](/docs/backup).

### Couldn't save your Twitch sign-in [#keychain-write-failed]

**Message:** "Couldn't save your Twitch sign-in" (or "Couldn't sign out of Twitch" when removing it fails).

**Why:** macOS blocked WolfWave from using the Keychain, where your sign-in is stored.

**Fix:**

1. Sign in again (or click **Try Again** to sign out).
2. If it happens every launch, open Keychain Access and check whether your login keychain is locked.
3. Still failing? Restart your Mac.

## Notifications

### Banners never show [#notifications-off]

**Message:** "Notifications are turned off for WolfWave. Enable them in System Settings to get these alerts."

**Why:** macOS is blocking WolfWave's notifications. The alert switches stay dimmed until you allow them.

**Fix:** Click **Open System Settings** on that message, turn on notifications for WolfWave, then come back. The switches live in **Settings → General → Notifications**. The two skip-vote alerts also need **Enable Vote-Skip** on.

## Updates

### Update check fails [#update-check-failed]

**Why:** WolfWave couldn't reach the update server. Usually a short network problem.

**Fix:** Try again from the menu bar: **Help → Check for Updates…**, or **Settings → Software Update**.

**Installed with Homebrew?** WolfWave doesn't update itself. Run:

```bash
brew upgrade wolfwave
```

## Still stuck

1. **Settings → Advanced → Export Logs**.
2. [Open an issue](https://github.com/MrDemonWolf/wolfwave/issues/new) and attach the file.
3. Say what you were doing and the exact message WolfWave showed.

Or ask in the [Discord community](https://mrdwolf.net/discord).
