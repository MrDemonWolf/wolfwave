## What can I type in chat?

The streamer uses WolfWave to share their Apple Music in Twitch chat. Type a command as the **first word** of your message. Capitals don't matter.

Not every command is on for every stream. The streamer picks which ones work. If nothing happens, the command is probably off, on cooldown, or you're not allowed to use it.

### See what's playing

| Type | What you get back |
|---|---|
| `!song` (or `!currentsong`, `!nowplaying`) | The song playing now. Example: `🐺 ▶️ Playing: Howl at the Moon by Gray Wolf` |
| `!last` (or `!lastsong`, `!prevsong`) | The song before it. Example: `🐺 Previous: Pack Run by Arctic Wolf` |
| `!stats` (or `!musicstats`) | The streamer's listening stats, like plays and top track |
| `!wolfwave` | A short line about WolfWave and where to get it |

- A paused song shows as `⏸️ Paused:` instead of `▶️ Playing:`.
- Some streamers add a song.link URL so you can open the song on any music service.

### Request a song [#song-requests]

Type `!sr` followed by a song name or a link.

| Type | What happens |
|---|---|
| `!sr Howl at the Moon` | WolfWave searches Apple Music and adds the best match to the queue |
| `!sr` + an Apple Music link | Adds that exact song |
| `!sr` + a Spotify or YouTube link | WolfWave reads the song's title and finds it on Apple Music |
| `!request` or `!songrequest` | Same as `!sr` |

The bot replies with one of these:

- **Added.** `Added "Howl at the Moon" by Gray Wolf, #3 in queue`
- **Waiting for the streamer.** `Sent "…" to the streamer for approval.` The streamer screens requests first.
- **Not found.** `No results for "…". Try a different search!` Try fewer words, or add the artist.
- **Blocked.** `Sorry, that song/artist is on the blocklist.`
- **Too many.** `You already have 2 songs queued. Wait for one to play!` (the number is set by the streamer)
- **Full.** `Queue is full (10/10). Try again later!`
- **Duplicate.** `That song is already in your queue.`
- **Not allowed.** For example `Song requests are subscriber-only right now.`

Links that work:

- Apple Music: a song link, or an album link that points at one track.
- Spotify: a track link (`open.spotify.com/track/…` or `spotify.link`).
- YouTube: a video link (`youtube.com/watch`, `music.youtube.com`, or `youtu.be`).

### Check the queue

| Type | What you get back |
|---|---|
| `!queue` (or `!songlist`, `!requests`) | The song playing now and the next 5 requests, with who asked for each |
| `!myqueue` (or `!mysongs`) | Only your requests and their spots in line |
| `!playlist` | A link to the streamer's requests playlist (only if they set one up) |

### Vote to skip a song [#vote-skip]

If the streamer turned on vote-skip, chat can skip a song together.

1. Someone types `!voteskip` (or `!vs`). A vote starts.
2. Others type `!voteskip` too. Each person counts once.
3. Enough votes in time skips the song. If time runs out, the song stays.

The bot shows the count, like `🗳️ 2/3 votes to skip this song.`

Some streamers use **Twitch Polls** instead. Then only the streamer or a mod can start the vote with `!voteskip`, and everyone votes in the Twitch poll. The song is skipped when "skip" wins and has at least the minimum number of votes.

After a vote ends, there's a short wait before the next one can start.

### Use channel points or Bits

Some channels let you request without typing a command.

- **Channel points.** Redeem the **Request a Song** reward and type a song name or link in the box. If the request fails (not found, blocked, queue full), your points are refunded.
- **Bits.** Cheer at least the streamer's minimum and add a song name in the same message. Example: `Cheer100 Howl at the Moon`. Bits can't be refunded, so double-check the song name.
- **Bits boost.** If the streamer turned it on, a cheer moves **your** oldest queued song to the front instead of adding a new one. If you have nothing queued, your cheer's song name is requested instead.

Channel points and Bits need those tools enabled on the channel and the API access WolfWave uses. Availability depends on Twitch's eligibility and onboarding requirements; basic `!sr` requests don't need either tool. See the [FAQ](/docs/faq#requests-and-chat).

### Who can use what

| Command | Who can use it |
|---|---|
| `!song`, `!last`, `!stats`, `!wolfwave`, `!queue`, `!myqueue`, `!playlist` | Everyone |
| `!sr` | Whoever the streamer allows: everyone, subscribers, VIPs and subscribers, or mods only. Mods and the streamer can always request. |
| `!voteskip` | Everyone, or subscribers only if the streamer chose that. Mods and the streamer can always vote. |
| `!skip`, `!next`, `!clearqueue`, `!cq`, `!hold`, `!resume`, `!unhold` | Mods and the streamer only. Anyone else gets no reply. |

### Why didn't the bot answer?

- **Cooldown.** Each command has a short wait between uses, for the whole chat and for each person. The bot stays quiet until it's over. Mods and the streamer skip cooldowns.
- **The command is off.** The streamer chose not to use it.
- **The stream is offline.** Some streamers set every command to work only while live.
- **It wasn't the first word.** `hey !song` won't work. `!song` will.

## For streamers

Everything below is set up in WolfWave's **Settings** window. Commands only work after you [connect Twitch](/docs/installation).

### Turn commands on

`!song` and `!last` are ready on a new install. Most other commands start **off**. Turn on the ones you want.

| Command | Default | Where to turn it on |
|---|---|---|
| `!song`, `!last` | On for new installs. If you set up WolfWave before 2.2, they stay how you had them. | Settings → Twitch → Bot Commands |
| `!wolfwave` | Off | Settings → Twitch → Bot Commands |
| `!stats` | Off | Settings → History & Stats → **!stats command** (needs Listening History and **Show Stats & Charts** on) |
| `!sr`, `!queue`, `!myqueue`, `!skip`, `!clearqueue` | On, but nothing works until Song Requests is on | Settings → Song Requests → Song Request Commands |
| `!playlist` | Off | Settings → Song Requests (turned on by the guided setup) |
| `!voteskip` | On, but nothing works until vote-skip is on | Settings → Song Requests → Chat Vote-Skip |
| `!hold`, `!resume`, `!unhold` | Always on | No switch. Mods and you only. |

Song requests have a master switch: **Enable Song Requests** in Settings → Song Requests. It's off until you turn it on. The first time, **Set up Song Requests** walks you through it. Details are in [Song requests](/docs/features#song-requests).

**Only reply while live.** In Settings → Twitch → Chat commands, this one switch keeps every command quiet until your stream goes live. It's off by default, so commands reply anytime.

### What the mod commands do

- **`!skip` / `!next`** plays the next request. Chat sees the new song. If the queue is empty, it says `Skipped. Queue is now empty.` If Music is busy, it says `Couldn't skip right now, try again.`
- **`!clearqueue` / `!cq`** removes every request and says how many were removed.
- **`!hold`** pauses request playback. New requests still join the queue but don't play. **`!resume`** or **`!unhold`** starts them again. This is the same as the **Hold Queue** switch.

### Who can request

Set this in Settings → Song Requests → **Who Can Request**. Pick a preset:

| Preset | What it does |
|---|---|
| **Open** | Anyone can use `!sr`. Channel points and Bits are on. Bits boost a queued song. |
| **Sub Only** | Only subscribers can use `!sr`. Channel points and Bits are off. |
| **Channel Point Only** | `!sr` is off. Viewers use the channel-point reward. |
| **Custom** | Pick the `!sr` audience yourself: Everyone, Subscribers, VIPs & Subscribers, or Mods Only. |

- Mods and you can always request.
- The audience only limits `!sr`. Channel points and Bits accept anyone who pays.
- A viewer who isn't allowed gets a short "not allowed" reply. That reply is rate-limited, and it never starts the `!sr` cooldown for everyone else.
- **Reply When Off** makes `!sr` say "Song requests are off right now." while requests are off. Off by default, so `!sr` stays silent.
- **Require My Approval** holds every request until you approve or decline it.

### Channel points and Bits

Turn these on in Settings → Song Requests → **Channel Points & Bits**.

- **Channel Point Requests.** WolfWave adds a **Request a Song** reward to your channel. Pick the cost (default 500). Failed requests are refunded automatically.
- **Bit Requests.** A cheer with a song name requests it. Pick the minimum (default 100 Bits).
- **Boost With Bits.** A cheer moves the viewer's queued song to the front instead.

You need:

- Channel Points or Bits enabled on your channel, plus Twitch API access for the feature. If Twitch rejects setup, follow the error shown in WolfWave.
- To sign in with your **broadcaster** account, not a separate bot account.
- The channel-point and Bits permissions. If they're missing, WolfWave asks you to reconnect once.

### Vote-skip settings

Settings → Song Requests → **Chat Vote-Skip**. Turn on **Enable Vote-Skip** first.

| Setting | Default | Choices |
|---|---|---|
| Minimum votes to skip | 3 | 2, 3, 5, 7, 10 |
| Vote window | 60s | 30, 60, 90, 120s |
| Cooldown between votes | 30s | 0 to 120s |
| Subscriber-Only Voting | Off | |
| Use Twitch Polls | Off | Affiliate/Partner only. Poll duration 30s to 5 min. |

A vote skips the request playing now. If no request is playing, it skips the current Apple Music track.

### `!stats` settings

In Settings → History & Stats → **!stats command**:

- **Window:** Today (default), This stream, Last 7 days, or All time. "This stream" uses Today while you're offline.
- **What to show:** Plays, Listening time, Top track, Top artist. Plays and Top track are on by default. At least one stays on.
- A live preview shows the exact reply.

### `!wolfwave` reply styles

Pick one in Settings → Twitch → Bot Commands. Each one credits MrDemonWolf and links the WolfWave site.

- **Credit + maker** (default)
- **Viewer how-to.** Points viewers at `!song`, `!last`, and `!sr`.
- **Open-source pitch**
- **Short & friendly**

### Cooldowns

A cooldown is how long a command waits before it answers again.

- **Everyone:** how long the whole chat waits after anyone uses it.
- **Per person:** how long one viewer waits after they use it.
- Mods and you always skip cooldowns.
- Aliases share their command's cooldown. `!song` and `!np` count as one.

| Command | Everyone | Per person | Can you change it? |
|---|---|---|---|
| `!song`, `!last`, `!wolfwave` | 15s | 15s | Yes. Everyone 0 to 30s, per person 0 to 60s, in 5s steps |
| `!stats` | 15s | 15s | Yes. Both 0 to 60s, in 5s steps |
| `!sr` | 5s | 30s | Yes. Everyone 0 to 30s, per person 0 to 60s |
| `!queue`, `!myqueue` | 10s | 15s | No |
| `!playlist` | 15s | 15s | No |
| `!skip`, `!hold` | 3s | 3s | No (mods skip it anyway) |
| `!clearqueue` | 5s | 5s | No (mods skip it anyway) |
| `!voteskip` | none | none | Uses the vote-skip cooldown instead |

**Sub / VIP priority** (Settings → Song Requests) can let subs and VIPs skip the `!sr` cooldown, or skip it and jump ahead in the queue. Off by default.

### Custom aliases

Add extra words for a built-in command. Type them comma-separated, without `!`. Example: add `np, track` to `!song` and viewers can also type `!np` or `!track`.

| Command | Where |
|---|---|
| `!song`, `!last`, `!wolfwave` | Settings → Twitch → Bot Commands |
| `!stats` | Settings → History & Stats |
| `!sr`, `!queue`, `!myqueue`, `!skip`, `!clearqueue`, `!playlist`, `!voteskip` | Settings → Song Requests |

- Aliases follow the same on/off, cooldown, audience, and live-only rules as the command.
- `!hold` and `!resume` have no aliases.

### Custom commands

Make your own commands in Settings → Twitch → **Custom Commands**. Click **Add command**.

Each command has:

- **Trigger.** One word, no spaces. Like `!hug`.
- **Aliases** (optional). Extra words for the same command.
- **Reply.** Up to 500 characters. A counter shows how many you've used.
- **Who can use it.** Everyone, Subscribers, VIPs, Moderators, or Broadcaster only. Higher roles always pass a lower bar. A mod can use a Subscribers command.
- **How it's sent.** See the table below.
- **Cooldowns.** Default 15s each. Everyone up to 30s, per person up to 60s.

You can make commands before you connect Twitch. They start replying once you connect.

**Variables** fill in when the command runs:

| Variable | Fills in with |
|---|---|
| `$user`, `$sender` | The name of whoever ran the command |
| `$touser` | The first word they typed after the command (a leading `@` is removed). If they typed nothing, their own name. |
| `$args` | Everything they typed after the command |
| `$1` to `$9` | One word, by position |
| `$song` | Your current song |
| `$lastsong` | The song before it |

**Example.** Trigger `!hug`, reply `$user gives $touser a big hug!`. A viewer named Luna types `!hug @Fang`. Chat sees `Luna gives Fang a big hug!`

**How it's sent:**

| Option | What chat sees |
|---|---|
| **Reply to chatter** (default) | A threaded reply under the viewer's message |
| **Plain chat message** | A normal message, not tied to anyone |
| **Announcement** | Twitch's highlighted announcement box |

Announcements need two things:

1. The account WolfWave signed in with must be a mod in your channel. Type `/mod <account>` in chat if it's a separate bot account.
2. The announcements permission on your Twitch sign-in. Older sign-ins don't have it. WolfWave asks you to reconnect once.

If Twitch refuses an announcement, WolfWave sends a normal reply instead and the Custom Commands card says why.

**Rules the editor checks:**

- No two custom commands can use the same trigger or alias. The editor names the command that already has it.
- A trigger or alias can't have spaces. Chat only matches the first word.
- A custom command can't use a built-in trigger or alias, like `!song`, `!sr`, or an alias you added to one. The editor names the built-in. A custom command saved by an older version that does this is turned off, so the built-in answers again.

Custom commands are included in your [settings backup](/docs/backup). A backup with a broken command (a duplicate trigger, a space in a trigger, or a cooldown the sliders can't set) is refused instead of half-imported.

### Limits

- Replies are capped at 500 characters, Twitch's limit. Longer text is cut cleanly, never mid-emoji.
- A command must be the first word of the message.
