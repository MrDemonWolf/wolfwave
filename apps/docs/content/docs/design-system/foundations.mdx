**TL;DR:** these are the raw values behind every color, font size, gap, corner, and animation in WolfWave.
Use the token name in code, never the number.

| In Swift | In CSS |
|---|---|
| `DSColor`, `DSFont.Size`, `DSFont.Weight`, `DSSpace`, `DSRadius`, `DSMotion`, `DSOpacity`, `DSDimension` | `--ds-*` custom properties |

All values come from [`design-system/tokens.json`](https://github.com/MrDemonWolf/wolfwave/blob/main/design-system/tokens.json). Edit there and run `bun run tokens` to regenerate every platform output.

## Token names

The color tables below list full CSS custom properties, except the Partner list, which leaves off the `--ds-color-` prefix. The other tables use short names: the bare `tokens.json` key (`2xl`) or a shortened CSS name (`space-0`, `duration-fast`). Use this table to find the name to type in CSS and in Swift.

| Token | `tokens.json` key | CSS | Swift |
|---|---|---|---|
| Spacing | `space.2` | `--ds-space-2` | `DSSpace.s2` |
| Font size | `font.size.2xl` | `--ds-font-size-2xl` | `DSFont.Size.x2xl` |
| Font size | `font.size.webBody` | `--ds-font-size-web-body` | `DSFont.Size.webBody` |
| Font weight | `font.weight.semibold` | `--ds-font-weight-semibold` | `DSFont.Weight.semibold` |
| Radius | `radius.2xl` | `--ds-radius-2xl` | `DSRadius.x2xl` |
| Duration | `motion.duration.pulseSlow` | `--ds-motion-duration-pulseSlow` | `DSMotion.Duration.pulseSlow` |
| Spring | `motion.spring.snappy` | None | `DSMotion.Spring.snappy` |
| Opacity | `opacity.washStrong` | `--ds-opacity-wash-strong` | `DSOpacity.washStrong` |
| Brand color | `color.brand.500` | `--ds-color-brand-500` | `DSColor.brand500` |
| Surface color | `color.surface.light.base` | `--ds-color-surface-base` | `DSColor.surfaceBaseLight` |
| Partner color | `color.partner.appleMusicStart` | `--ds-color-partner-apple-music-start` | `DSColor.partnerAppleMusicStart` |
| Dimension | `dimension.settings.sidebarWidth` | None | `DSDimension.Settings.sidebarWidth` |

How the generator builds them:

- A Swift name can't start with a digit, so the generator adds a prefix: `s` for spacing (`s2`) and `x` for font sizes and radii (`x2xl`).
- CSS names are kebab-case (`web-body`). Motion durations are the exception: they keep the key as written (`pulseSlow`).
- A color that changes with the theme is one CSS name whose value flips under `.dark` (`--ds-color-surface-base`). In Swift it is two constants, `DSColor.surfaceBaseLight` and `DSColor.surfaceBaseDark`.
- Swift durations are in seconds. CSS durations are in milliseconds.
- Springs and dimensions have no CSS name.

## Color

### Brand scale

WolfWave's primary brand color is Apple System Blue (**`#0A84FF`**). The full scale is available for backgrounds, hover states, and accents.

<div style={{ display: "grid", gridTemplateColumns: "repeat(10, 1fr)", gap: "0.5rem", margin: "1rem 0" }}>
  {[50,100,200,300,400,500,600,700,800,900].map((step) => (
    <div key={step} style={{ display: "flex", flexDirection: "column", alignItems: "center" }}>
      <div style={{ width: "100%", aspectRatio: "1", borderRadius: "var(--ds-radius-md)", background: `var(--ds-color-brand-${step})`, border: "1px solid var(--ds-color-surface-hairline)" }} />
      <code style={{ fontSize: "0.7rem", marginTop: "0.25rem" }}>{step}</code>
    </div>
  ))}
</div>

In dark mode (the `.dark` class or `data-theme="dark"`), the CSS variable `--ds-color-brand-600` shifts to `#409CFF`, so brand-colored text stays readable on dark surfaces. The other steps stay the same, so the 600 swatch above changes with the theme. The shift is CSS only. Swift has one value per step, and `DSColor.brand600` is the light one.

### Brand gradient

`partner-wolfwave-gradient-start` `#0A2540` → `partner-wolfwave-gradient-end` `#2563EB` is WolfWave's own brand gradient, not a partner's. It is filed under the `partner` token group, which is why the names say `partner`. Use it on WolfWave brand surfaces such as the logo mark and the Monthly Wrap share card, never on a partner logo. In Swift, read it as `AppConstants.Brand.wolfwaveGradientStart` and `AppConstants.Brand.wolfwaveGradientEnd`. [Brand](/docs/design-system/brand) shows the light and dark pairings.

### Semantic

| Token | Light | Dark |
|---|---|---|
| `--ds-color-success` | `#34C759` | `#34C759` |
| `--ds-color-warning` | `#FF9F0A` | `#FF9F0A` |
| `--ds-color-error`   | `#FF453A` | `#FF453A` |
| `--ds-color-info`    | `#0A84FF` | `#0A84FF` |
| `--ds-color-neutral` | `#8E8E93` | `#8E8E93` |

`neutral` is the off / disconnected state. It is Apple's `systemGray`, the one system
gray whose light and dark variants are identical, so a single flat value reads
correctly in both themes.

### Glyph

A status dot or icon sitting on its own 10% wash loses contrast in light mode, so
each status color has a darker light-appearance glyph variant. Dark mode reuses the
semantic tint above.

| Token | Light | Dark |
|---|---|---|
| `--ds-color-glyph-success` | `#1E7B34` | `#34C759` |
| `--ds-color-glyph-warning` | `#9A5B00` | `#FF9F0A` |
| `--ds-color-glyph-error`   | `#C9302C` | `#FF453A` |
| `--ds-color-glyph-info`    | `#0066CC` | `#0A84FF` |
| `--ds-color-glyph-neutral` | `#6E6E73` | `#8E8E93` |

### Opacity

Tinted washes take their fill opacity from a token instead of a literal. Status chips and
callouts use `--ds-opacity-wash` `0.10`. `--ds-opacity-wash-strong` `0.14` is the heavier
fill for a selected row on a tint, as in `SettingsNavRail`.

### Surface & text

Surface and text colors have light values on `:root` and dark values under `.dark` (or `data-theme="dark"`). Reference the abstract token, not the underlying hex.

| Token | Light | Dark |
|---|---|---|
| `--ds-color-surface-base`     | `#FFFFFF` | `#000000` |
| `--ds-color-surface-surface`  | `#F5F5F7` | `#1C1C1E` |
| `--ds-color-surface-elev`     | `#FBFBFD` | `#0A0A0C` |
| `--ds-color-surface-hairline` | `#D2D2D7` | `#2C2C2E` |

### Text

| Token | Light | Dark |
|---|---|---|
| `--ds-color-text-primary`   | `#1D1D1F` | `#F5F5F7` |
| `--ds-color-text-secondary` | `#505057` | `#C0C0C6` |
| `--ds-color-text-muted`     | `#505057` | `#B0B0B8` |

All three text roles meet AAA text contrast (at least 7:1) on the solid `base`, `surface`, and `elev` tokens in their appearance. `bun run ds:test` guards these pairs. This does not certify every component or transparent overlay: check actual composited backgrounds, focus indicators, and control states too.

## Type scale

| Token | px | Use |
|---|---|---|
| `xs`   | 10 | Captions, smallest meta |
| `sm`   | 11 | Tag, status chip |
| `body` | 12 | Body, dense rows |
| `base` | 13 | Default UI text |
| `md`   | 14 | Row titles |
| `lg`   | 17 | Section headers |
| `xl`   | 20 | Subtle hero |
| `2xl`  | 22 | Titles and key figures |
| `3xl`  | 26 | Onboarding welcome and completion titles, large glyphs (now-playing card, brand tile) |
| `display` | 52 | Monthly Wrap headline figure |
| `webSmall` | 14 | Web labels and supporting text |
| `webBody` | 16 | Web body baseline |
| `webSection` | 48 | Desktop web section headings (30px on small screens) |
| `webHero` | 74 | Desktop web hero (38px on small screens) |

Weights: `regular` 400, `medium` 500, `semibold` 600, `bold` 700.

In SwiftUI, use the heading ramp instead of picking sizes:

| Modifier | Size | Role |
|---|---|---|
| `.paneTitle()` | 22, bold | Title for standalone content, such as the add/edit command sheet. Settings panes don't use it. |
| `.sectionHeader()` | 17, semibold | Section heading. The top heading in a Settings pane. |
| `.sectionEyebrow()` | 11, semibold, secondary | Label inside a card |
| `.fieldSubtitle()` | 13, secondary | Body under a heading |
| `.captionText()` | 10, secondary | Caption, footnote |

In Settings, the window toolbar names the pane, so the content doesn't repeat that title. Start at `.sectionHeader()`, and use `.sectionEyebrow()` for labels inside cards.

All five scale with the user's text size setting.

Families: `--ds-font-family-display` (Montserrat), `--ds-font-family-sans` (Roboto), `--ds-font-family-mono` (JetBrains Mono). This site loads those three, self-hosted by Next.js at build time. Two more stacks are defined but this site doesn't load or use them: `--ds-font-family-serif` (Instrument Serif, then the system serif) and `--ds-font-family-system-apple-display` (the SF Pro Display system stack). Swift has no family tokens, only sizes and weights.

Typography follows the [MrDemonWolf website](https://github.com/mrdemonwolf/website/blob/main/apps/website/src/styles/site.css): 16px body, 1.6 or greater body line height, semibold (600) Montserrat display headings, and responsive heading sizes. Native UI sizes remain the platform scale above.

| Token | Response | Damping |

Respect `prefers-reduced-motion`. Drop to instant transitions.

## Dimensions

`DSDimension` holds fixed sizes, like window sizes, the settings sidebar width, and chart heights.
Use it for `.frame(width:height:)`. `DSSpace` is only for gaps and padding.
Dimensions are Swift only. The full list is in `tokens.json` under `dimension`, in these groups:

| Swift group | Sizes |
|---|---|
| `DSDimension.Settings` | Window minimum and ideal size, sidebar and content widths, content padding, section spacing, card padding and radius, nav rail width |
| `DSDimension.Onboarding` | Window size, button sizes and radius, content width, brand tile and icon tile sizes and radii |
| `DSDimension.About` | Window size and minimum size |
| `DSDimension.WhatsNew` | Window size |
| `DSDimension.IconButton` | `DSIconButton` minimum width and height |
| `DSDimension.HistoryStats` | Card, chart, and list heights, the two-column width floor, the chart axis gutter |
| `DSDimension.StatusChip` | `StatusChip` dot size and minimum width |
