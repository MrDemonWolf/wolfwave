**TL;DR:** one file, `design-system/tokens.json`, sets the colors, type, spacing, and motion for the app, this site, and the OBS widget.
This section is for contributors changing how WolfWave looks.

For a visual tour, open the public [Design system](/design-system): live type specimens, measured color pairs in both appearances, shared actions, and motion timing samples.

It covers three products:

- **The native macOS app** (Swift / SwiftUI, macOS 26 Liquid Glass)
- **This docs site** (Fumadocs / Tailwind 4)
- **The OBS widget overlay** (TypeScript / Tailwind 3, inlined into one HTML file)

## Canonical source

All tokens live in [`design-system/tokens.json`](https://github.com/MrDemonWolf/wolfwave/blob/main/design-system/tokens.json) at the repo root. A Bun script (`bun run tokens`) generates per-platform outputs that are committed alongside the source. Runtime consumers use those committed outputs; contributors rerun the generator after changing tokens or generator code.

```text
design-system/tokens.json   ← edit this
    │
    ├─→ Tokens.generated.swift     (DSColor, DSFont, DSSpace, DSRadius, …)
    ├─→ tokens.generated.css       (--ds-* custom properties)
    ├─→ widget-tokens.generated.js (window.WW_TOKENS)
    └─→ widget-themes.generated.ts (landing-page overlay preview)
```

## Change a token

1. Edit `design-system/tokens.json`.
2. Run `bun run ds:schema`. It checks `tokens.json` against `design-system/tokens.schema.json`. Run it before the generator, which doesn't check the shape on its own.
3. Run `bun run tokens` to regenerate all four outputs.
4. Changed a color, font, spacing, radius, motion, or shadow token, or a widget theme or layout? Run `make widget` too. The widget inlines those token groups into `widget.html`. Use the Bun version pinned in `package.json`, because another version minifies differently and fails the drift check.
5. Run `bun run ds:lint` and `bun run ds:test`. The tests pin each lint rule, check that the rules cover every spacing and radius token, and check text-token contrast.
6. Breaking change (a rename, a removed key, or value drift)? Bump `meta.version` in `tokens.json` and call it out in the PR description.
7. Stage the source and every regenerated file together, then run `make check-drift`. It regenerates everything again and fails if any generated file differs from what you staged, which is the check CI runs. Commit once it passes.

Adding a new top-level namespace? Update `design-system/tokens.schema.json` in the same change. The schema rejects unknown top-level keys, so `ds:schema` fails until you do.

Never hand-edit a `*.generated.*` file.

## Rules the linter enforces

`bun run ds:lint` blocks these in SwiftUI views. Each failure prints its rule in brackets, such as `[raw-font-size]`.

- `raw-font-size`: literal font sizes. Use `DSFont.Size.*`.
- `raw-spacing` and `raw-padding`: literal `spacing:` or `.padding(N)`. Use `DSSpace.*`.
- `raw-radius`: literal corner radii. Use `DSRadius.*`.
- `raw-animation-duration`: literal animation durations or spring responses. Use `DSMotion.*`.
- `raw-status-color`: raw system colors as a status tint. Use `DSColor.success` / `.warning` / `.error` / `.info` / `.neutral`.

What the linter sees:

- It scans only `apps/native/WolfWave/Views/`, one line at a time. Tests and `*.generated.swift` files are not scanned. Comments are scanned, so a literal in a comment is flagged too.
- `Views/Onboarding/` is exempt from the font, spacing, padding, and radius rules. The motion and status-color rules still apply there.
- The spacing, padding, and radius rules only flag values that already have a token. An off-scale literal such as `spacing: 7` passes, so add the token first.
- A call split across lines passes, and `.frame(width:height:)` literals are not checked yet.

The allowlist, `design-system/lint-allowlist.txt`, is empty on purpose. Fix the source instead of adding a line.

Adding a rule? Add it to the `Rules` comment in `design-system/scripts/lint.ts` and pin it in `lint.test.ts`. `make lint-sync` fails when the comment and the rule table disagree.
